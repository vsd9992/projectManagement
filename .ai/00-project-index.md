## Decision pointers (current)
- `multi-tenant-saas-product` — SaaS from day one, not internal tool
- `composable-workstream-project-model` — Project = composable Workstreams, not a rigid type enum
- `generic-billing-engine-india-first-profile` — generic billing/tax engine, India is first profile
- `mvp-scope-turnkey-interiors-first` — MVP = Turnkey Interiors, full depth, before other verticals
- `change-order-requires-client-approval` — Change Orders not binding without formal client approval
- `mvp-finance-and-vendor-access-scope` — minimal Finance role in MVP; procurement internal-facing only
- `technology-stack-backend-frontend` — Rust/Axum/SeaORM+SQLx/PostgreSQL backend, React/TypeScript frontend; SurrealDB dropped
- `tenant-isolation-shared-schema-rls` — shared schema + Postgres row-level security for multi-tenant isolation
- `auth-session-based-single-login` — server-side sessions + Argon2, single global login, unified auth for internal + Client Portal
- `api-contract-utoipa-orval-react-query` — utoipa OpenAPI spec + orval-generated client/React Query hooks
- `hosting-dev-local-prod-kubernetes` — local dev server; production Kubernetes on Linode or E2E (TBD)
- `client-portal-auth-pulled-into-m2` — Client Portal login/auth built in M2 (not deferred to M5) since design approval needs a real client actor
- `rbac-business-unit-scoping-implemented` — role + business-unit-membership enforcement across all internal endpoints; supersedes archived `no-rbac-enforcement-yet`
- `tenant-admin-and-platform-manager` — per-tenant admin (roll-up visibility, org management) + fully separate platform-manager tier (pause/resume/delete tenant lifecycle only, no tenant business data access)
- `workstream-enforcement-and-expansion` — workstream membership enforced at the API layer for all workstream-specific entity creation; the only way to add a workstream to an existing project is Change Order client approval
- `phase-3-audit-and-expansion` — Phase 3 scope (audit pass, test backfill, progressive billing, Schedule/Dependency graph, PO approval, tenant config API) and every money-math/architecture sub-decision made along the way

Both new apps infer session state from a data call resolving 200-vs-401 rather than a dedicated identity endpoint, since neither `AuthenticatedClientUser` nor `AuthenticatedPlatformAdmin` had one (documented in `RequireClientAuth.tsx`/`RequirePlatformAuth.tsx`).
  Two backend gaps found and fixed as part of making the new UI actually usable, not scope creep: `GET /api/client/projects/{id}/quotations` didn't exist, so a client had no way to discover their project's initial quotation before any Change Order existed (only approve/reject-by-id worked) — added, mirroring the internal `list_quotations` handler; `POST /api/platform/auth/logout` didn't exist at all, so a platform admin had no way to end a session short of the 30-day cookie expiring — added.
  One real bug found live (not by the new UI code, but exposed by exercising it for the first time): `list_tenants` had no `ORDER BY`, so pausing/resuming a tenant could change Postgres's returned row order on the next fetch, making a tenant appear to jump position or vanish from view in the Platform Admin table. Audited every `list_*` handler in the backend for the same missing-ordering pattern at the user's request and found it was systemic — roughly 20 handlers across almost every route file lacked any `order_by`. Fixed all of them with a stable `order_by_asc` on each entity's natural timestamp column (`created_at` in most cases; `raised_at` for punch-list items and site queries, `log_date` for daily logs, `version` for the client-portal design-revision nesting) — a pre-existing correctness gap since each entity's original implementation, only surfaced now because this was the first time a UI rendered these lists live in a browser rather than via one-shot curl calls.

Backend exercised end-to-end via curl for every new/changed endpoint (procurement, manufacturing, site execution, schedule including a dependency-driven date shift, milestone/progressive billing math, the full change-order-approval-cascade re-baselining a quotation, platform pause/resume/logout). Full click-through verified live in a real browser across all three apps: internal nav to every new page and section; a design-asset-creation → revision-submission → client-approval round trip exercised through actual button clicks (not just direct navigation); platform admin login → pause → resume → the ordering fix confirmed stable across a real mutation → logout correctly invalidating the session server-side (re-navigating to `/platform` bounced back to login); client portal login → project detail → logout. `.ai/00-project-index.md` and `project/roadmap.md` updated; no baseline docs required changes since no product behavior or architecture decisions changed, only implementation completeness.
